# Units of Work: 凪（nagi）

開発を独立した価値提供ブロックに分解する。優先度順。

## Unit 1: 気分入力と状態の永続化

### ゴール
ユーザーが朝晩に自分の気分（晴れ／曇り／雨）と一言を凪に伝えられる。

### 価値
凪が察するための一次データソースを確保する。ユーザー側からも能動的に気持ちを言語化できる体験を提供する。

### 必要な機能
- ユーザー認証（Firebase Auth、メール認証のみで十分）
- 気分入力UI（晴れ／曇り／雨の3択 + 一言テキスト、所要10秒）
- 朝晩2回のリマインダー
- Firestoreへの永続化

### 完了条件
- ユーザーが朝・夜それぞれの気分を入力できる
- 入力履歴が残る
- 履歴が時系列で確認できる

## Unit 2: 凪へのつぶやき

### ゴール
ユーザーが任意のタイミングで「今、こんな気分」を凪に話せる。

### 価値
気分入力では拾えない、その瞬間の気持ちを凪に伝えられる。Geminiで解釈する素材になる。

### 必要な機能
- つぶやき入力UI（プレースホルダ「今、どんな気分？」のみのテキストエリア）
- 送信して履歴に残す
- Firestoreへの永続化（whispersコレクション）

### 完了条件
- ユーザーがいつでもつぶやける
- 履歴が残る
- 凪エージェントが読み取れる形で保存される

## Unit 3: 観察・解釈・通知の3エージェント

### ゴール
3つのAIエージェントが協調して、観察 → 解釈 → 通知を自律実行する。

### 価値
ハッカソン審査の核心「AIエージェントが価値の中心」を満たす。単なるLLM呼び出しではなく、自律的な判断を行うエージェントシステム。

### 必要な機能
- 観察エージェント：Firestore + 天気APIからデータ収集
- 解釈エージェント：Gemini APIで機微を解釈、通知すべきか判断
- 通知エージェント：通知文生成と配信
- ADKでの3エージェント協調実装
- Cloud Runへのデプロイ

### 完了条件
- 朝8時、夜21時にエージェントが自動起動する
- 3エージェントが順次データを受け渡しする
- should_notify判定で「通知しない」が成り立つ
- 通知文が和のトーン規則に沿って生成される

## Unit 4: プッシュ通知配信

### ゴール
通知エージェントが生成したメッセージを、相手のスマホにプッシュ通知として届ける。

### 価値
受動的に情報を受け取れる体験。アプリを開かなくても、必要な時だけ凪が話しかけてくる。

### 必要な機能
- Firebase Cloud Messaging統合（Web Push）
- iOS Safari 16.4+ 対応
- 通知タップでアプリの該当画面へ遷移
- 通知履歴のFirestore保存（tayoriコレクション）

### 完了条件
- 実機のスマホで通知を受け取れる
- 通知をタップするとホーム画面が開き、便りが表示される
- 通知履歴が一覧で見られる

## Unit 5: ペアリング機能

### ゴール
二人がそれぞれのスマホで、相手の凪を「預かる」状態を作る。

### 価値
凪の核心構造である「相互交換」を実現する。

### 必要な機能
- QRコード生成・スキャン
- pair_idでusersを紐づけ
- 相手のFCMトークン取得
- 相手側の凪エージェントから自分のスマホに通知が届く設定

### 完了条件
- 二人がペアリングできる
- 自分のエージェントが、相手のスマホに通知を送れる
- ペアリング解除も可能

## Unit 6: 週次レポート「今週の風」

### ゴール
毎週日曜の朝、過去1週間の機微を要約したレポートが届く。

### 価値
日々の通知が点だとすると、週次レポートは線。関係の変化を振り返れる。

### 必要な機能
- Cloud Schedulerで毎週日曜朝8時に起動
- 過去7日のデータを集計
- Geminiで「今週の風」フォーマットでレポート生成
- 通知配信

### 完了条件
- 毎週日曜朝に自動でレポートが届く
- 具体的な観察を含む（「月曜：あなたの『おかえり』にほっとしてました」など）
- 和のトーン規則に従っている

## Unit 7: 和のUI実装

### ゴール
プロダクトの哲学を表現する、静かで余白のあるUI。

### 価値
ユーザビリティと体験価値の両方を担保する。和を語彙ではなく振る舞いで示す。

### 必要な機能
- ホーム画面（今日のたより1つだけ表示）
- たよりの履歴画面
- 気分入力画面
- つぶやき入力画面
- 設定画面
- ペアリング画面
- オンボーディング（3画面）

### 完了条件
- 5主要画面 + 3補助画面が動く
- 配色は3色まで（淡いグレー/濃いグレー/差し色1色）
- 余白を活かした静かなデザイン
- アニメーションは500ms程度のフェード
- グラフ・数値・絵文字・派手な装飾なし

## 優先順位と依存関係

開発順は以下を推奨：

1. Unit 1 (気分入力) → 基盤
2. Unit 7 (和のUI実装、Unit 1〜2のUI部分) → ユーザーが触れる部分
3. Unit 3 (3エージェント) → コア機能、最も時間がかかる
4. Unit 2 (つぶやき) → Unit 1 と並行可
5. Unit 4 (プッシュ通知) → Unit 3 完了後
6. Unit 5 (ペアリング) → Unit 4 完了後
7. Unit 6 (週次レポート) → 最後
