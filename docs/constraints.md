# Constraints: 凪（nagi）

開発における制約を明確にする。AI-DLCはこれを参照して、提案を制約内に収める。

## プロジェクト規模

- **個人開発**：1人で実装する（チーム前提のプロセスは不要）
- **期間**：約9週間（2026年5月〜7月）
- **作業時間**：1日4〜6時間、合計約270時間
- **目的**：ハッカソン提出（製品化ではなく、デモで見せられる完成度）

## 必須技術スタック（ハッカソン要件）

### Google Cloud アプリケーション実行プロダクト（必須・1つ以上）
- **Cloud Run**：エージェントの常駐実行環境

### Google Cloud AI 技術（必須・1つ以上）
- **Vertex AI**：Gemini API経由でLLMを利用
- **Gemini API**：解釈・通知文生成
- **ADK (Agents Development Kit)**：3エージェント実装

### 任意採用
- **Firebase Auth**：ユーザー認証
- **Firestore**：データ永続化
- **Firebase Cloud Messaging**：プッシュ通知
- **Cloud Scheduler**：定期実行

### 採用しない（明示的にスキップ）
- **Flutter**：学習コスト高、PWAで十分
- **Veo**：動画生成は不要
- **Speech-to-Text/Text-to-Speech**：音声機能はMVPに含まない

## フロントエンド技術

- **Next.js + TypeScript**：個人開発で慣れている
- **PWA化**：スマホで使える、ストア配布不要
- **Web Push**：iOS Safari 16.4+ で動作

## エージェント設計の必須要件

### 3エージェント構成は厳守

審査基準「AIエージェントが価値の中心」を満たすため、以下の3エージェント構成を必ず維持する。**単一LLM呼び出しに簡略化してはならない**。

1. **観察エージェント**：データ収集・整理
2. **解釈エージェント**：Geminiで機微を解釈、通知すべきか判断
3. **通知エージェント**：通知文生成と配信

### ADKを必ず使う

技術要件として ADK が必須。エージェント間のシーケンシャル協調を実装する。

## 倫理的制約

### 禁止事項

- **常時録音や会話の盗み聞き**：プライバシー侵害、技術的にも非現実的
- **行動の強制**：AIは指示せず、気づきを贈るのみ
- **数値化・スコア化**：「夫婦愛度85%」のような表現は絶対NG
- **依存設計**：使うほど依存させる仕組みは作らない

### 必須事項

- データ収集は本人の明示的同意を前提とする
- 気分入力は10秒で済む軽さを保つ
- 通知頻度を抑える（沈黙を贈り物にする）

## データソース

### 採用するデータソース

- **気分入力**（必須・能動的）：朝晩2回、3択+一言
- **凪へのつぶやき**（任意・能動的）：テキスト入力
- **天気**（自動）：OpenWeather API
- **時刻・曜日**（自動）

### MVPではモック対応

実装の手間が大きいので、デモではモックデータで対応：

- **スマホ使用パターン**：スクリーンタイムAPIを使わず、デバッグ画面から手動投入
- **ヘルスデータ**：HealthKit/Google Fit統合せず、手動投入
- **カレンダー連携**：Google Calendar API統合せず、手動投入

### 採用しないデータソース

- **音声録音**：プライバシーと技術的制約
- **SNS投稿の自動取得**：API制約と倫理的観点
- **位置情報の常時取得**：プライバシー侵害

## 通知文の制約（厳守）

世界観の核なので、AIに任せず、明示的に守らせる必要がある。詳細は `domain-knowledge.md` を参照。

### 絶対禁止
- 数値・パーセント・スコアの表記
- 命令形（〜してください、〜すべき）
- 絵文字
- 過剰な比喩（「薄曇りのよう」を1通に複数入れない）
- 「便り」「頃合い」「気配」の連発
- 専門用語（PMS、うつ症状、コルチゾール等）
- 過度なエモーショナル表現

### 厳守
- 1通は2〜3行以内
- 普通の日本語で書く
- 比喩は1通に0〜1個まで
- 主語は観察対象、判断は受け手に残す
- 通知頻度を抑える（毎日通知しない）

## 開発プロセスの制約

- **AI-DLCの3フェーズに従う**：INCEPTION → CONSTRUCTION → OPERATIONS
- **軽量版で進める**：14ステージ全部はやらない、必須5ステージとプロジェクト状況に応じた選択
- **Boltサイクル**：作業単位を数時間〜1日に区切る
- **承認ゲートを尊重する**：AIが提示した計画を、人間がレビューして承認する

## 成果物の保存

- **ソースコード**：GitHub（公開リポジトリ）
- **設計成果物**：`aidlc-docs/` ディレクトリに保存
- **デモ動画**：3分の動画
- **ProtoPedia投稿用テキスト**：プロダクト説明、スクリーンショット
- **プレゼン資料**：スライド形式

## デプロイ環境

- **本番**：Cloud Run（asia-northeast1=東京リージョン）
- **データベース**：Firestore（asia-northeast1）
- **認証**：Firebase Auth
- **ストレージ**：Firebase Hosting（PWA配信）
- **モニタリング**：最低限（Cloud Loggingのみ）

## 予算制約

- Google Cloud：ハッカソン提供のクレジット内で運用
- 個人費用：月額数千円以内（Cursor Pro、ドメイン等）

## 判断保留事項（INCEPTIONで決める）

- ペアリング相手未参加時のフロー
- データ削除・関係解消時の処理
- ビジネスモデル（ハッカソンでは問われたら答える程度）
- オンボーディングの詳細フロー
